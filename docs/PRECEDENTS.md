# 10. Precedents

**Closest overall match: Amazon States Language (AWS Step Functions).** A state machine is defined as JSON text with named states, a `Next`/`End` control-flow model, and a declared query language for pulling values out of the running data — historically JSONPath, with JSONata now offered as an alternative per state. That's the same shape as Jaxson's package: JSON program, explicit references into state, deterministic transitions. It's aimed at orchestrating external service calls rather than pure computation, and it doesn't ship a contract-schema layer the way Jaxson's input/output schemas do.

**Closest match to `$tpl`/jsonplate: JSON-e**, from Mozilla/Taskcluster. It treats a data structure as a template and transforms it using another data structure as context to produce an output data structure, working on the parsed structure rather than text so the output can't come out as invalid JSON. Two details land very close to your design: it never uses eval or anything that could run arbitrary code, and it disallows unbounded iteration, so a render always finishes — which is exactly the termination argument I made for Jaxson's `for`. It uses `$eval` rather than `$path`/`$ref`, and it's a pure templating language with no persistent state or contract schemas around it.

**Closest match to the compute sublanguage: CEL and JMESPath**, for different reasons. CEL evaluates in linear time, is mutation-free, and is deliberately not Turing-complete, which is the same total-by-construction stance as your `$compute`. JMESPath is narrower still: it has no arithmetic, no user-defined functions, and no side effects, making it a pure query language with a standardised spec and a cross-implementation conformance suite — that conformance-suite-as-executable-spec model is close to what your Part 5 was reaching for. Neither one owns a mutable-state or control-flow layer; they're expression languages other systems embed, the way I'd suggest embedding `$compute` inside Jaxson.

**Closest match to queryfy's role (schema-gated validation + query in one library): JSONiq**, though it's a much heavier XQuery-derived language rather than a small validator. It's a strongly typed, side-effect-free language for declaratively querying and transforming JSON and XML. It's the only thing I found that treats querying and typing as one system the way queryfy tries to; it does so at the cost of being a full W3C-style language rather than a small Go library.

**Structurally adjacent: "Orbitals" / JSON That Thinks.** A February 2026 write-up describes a system where logic is expressed as JSON arrays, execution is deterministic and recursive, and a guard is a conditional expression controlling whether a state transition fires, with entities declaring fields and types, and traits as reusable state machines attached to them. That's structurally close to Jaxson: JSON-native, state-machine-shaped, declared field types. It's framed as a hobby/startup project rather than a spec, and from the excerpt it looks less concerned with numeric determinism or a closed operation set than our design.

**Two more with partial overlap:**
- **JSL (JSON Serializable Language)**, a Lisp-like language designed to be sent over the wire, with comprehensive gas/step metering for safe distributed execution and a security model where the host environment controls all capabilities and no arbitrary code execution is possible. Step metering as the semantic resource bound is exactly your section 9. It's a general Lisp, though, not JSON-with-a-narrow-instruction-set.
- **UIDL** (a Flutter-oriented UI description format) has a bounded expression language with arithmetic, comparison, logic, strings, arrays and ternaries, capped at a bounded recursion depth, plus an action dispatcher for `if`, `setState`, and sequencing. Same idea in miniature, aimed at UI rather than general computation.

**What none of these do together, as far as we know:** pair a closed, versioned input/output contract (queryfy's role) with a templating layer that distinguishes present-null from absent (your `$opt`), sitting on top of a step-bounded instruction language with an isolated, no-loops compute sublanguage. JSON-e comes closest to the templating half, ASL and Orbitals come closest to the instruction half, and CEL/JMESPath come closest to the compute half — but I didn't find one project spanning all three the way this suite is meant to.
